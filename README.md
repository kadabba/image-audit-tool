# Image Audit Tool

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

Находит все изображения на сайте, показывает их одной галереей и помогает
отобрать лишние: битые ссылки, забытые дубли, стоковые фото без лицензии.
На выходе — список URL для массового удаления.

Подробное описание сервиса для нетехнического читателя — в [SERVICE.md](SERVICE.md).

## Возможности

- **Обход всего сайта** по `sitemap.xml` (включая sitemap index); если карты
  нет — краулинг по внутренним ссылкам
- **Полный сбор картинок**: `src`, ленивая загрузка (`data-src`,
  `data-original`), `<picture>/srcset`, фоны из inline-стилей
- **Технический аудит**: HTTP-статус, формат, вес файла, размеры в пикселях
- **Оценка риска по авторским правам** на основе EXIF (`Copyright`, `Artist`,
  `Software`) с распознаванием следов фотобанков
- **Галерея с группировкой**: одна картинка = одна карточка со списком всех
  страниц, где она встречается
- **Экспорт списка** отмеченного в `.txt` для удаления через WP-CLI

## Быстрый старт

```bash
git clone https://github.com/kadabba/image-audit-tool.git
cd image-audit-tool

cp .env.example .env      # задайте DB_PASSWORD
docker compose up -d
```

Откройте <http://localhost:8000>, введите адрес сайта, нажмите «Сканировать».

Сайт на ~500 страниц обходится за единицы минут. Прогресс виден на странице;
вкладку можно закрыть — скан продолжится на сервере.

## Настройка

Переменные читаются из `.env` в корне проекта (см. [.env.example](.env.example)).

| Переменная    | По умолчанию  | Назначение |
|---------------|---------------|------------|
| `DB_PASSWORD` | —             | **Обязательна.** Без неё `docker compose` не стартует |
| `DB_USER`     | `postgres`    | Пользователь БД |
| `DB_NAME`     | `image_audit` | Имя базы |
| `ENABLE_DOCS` | `true`        | Swagger по пути `/docs`. `false` закрывает его вместе с `/redoc` и `/openapi.json` |
| `RETENTION_DAYS` | `30`       | Через сколько дней удалять сканы. `0` отключает уборку |

Лимиты правятся константами в [`backend/app/ratelimit.py`](backend/app/ratelimit.py):

| Константа              | По умолчанию | Назначение |
|------------------------|--------------|------------|
| `SCANS_PER_HOUR`       | 5            | Сканирований в час с одного IP |
| `MAX_CONCURRENT_SCANS` | 3            | Одновременных сканов на весь сервис |

## Удаление картинок на сайте

Сервис ничего не удаляет сам — только отдаёт список. Удаление делается на
стороне сайта скриптом [`remove-images.php`](remove-images.php): он убирает
`<img>` с указанными URL из контента постов и страниц, **не трогая файлы
в медиабиблиотеке**.

```bash
# сухой прогон — только показывает, что изменится
wp eval-file remove-images.php delete-images.txt

# применить
wp eval-file remove-images.php delete-images.txt apply
```

Всегда сначала прогоняйте без `apply` и делайте бэкап БД.

## API

| Метод  | Путь                    | Назначение |
|--------|-------------------------|------------|
| `POST` | `/api/scan/`               | Запустить скан: `{"site_url": "https://example.com"}` → `scan_token` |
| `GET`  | `/api/scan/{token}`        | Статус и прогресс скана |
| `GET`  | `/api/images?scan_token=…` | Галерея скана |
| `POST` | `/api/images/status`       | Статусы картинок внутри своего скана |
| `GET`  | `/api/export?scan_token=…` | Список URL в `.txt` |
| `GET`  | `/api/image?url=...`       | Прокси картинки в обход CORS и хотлинк-защиты |

`scan_token` — непредсказуемая строка, выданная при запуске. Она и есть ключ
доступа: знающий токен видит скан, остальные нет. Номера сканов наружу
не отдаются, чтобы их нельзя было перебрать.

Пути указаны относительно адреса, на котором развёрнут сервис: при локальном
запуске это `http://localhost:8000`, в продакшене — ваш домен.

Интерактивная документация Swagger — по пути `/docs`. В продакшене её можно
закрыть, задав `ENABLE_DOCS=false` (см. таблицу переменных выше).

## Развёртывание

**Приложение обязано стоять за реверс-прокси** и не смотреть в интернет
напрямую. В `docker-compose.yml` порты открыты только на `127.0.0.1` —
так и оставьте, а TLS и публичный вход отдайте nginx или Caddy.

Причина не только в TLS: uvicorn запущен с `--proxy-headers` и берёт IP
клиента из `X-Forwarded-For`. Если открыть порт наружу, любой сможет
подделать этот заголовок и обойти лимит сканирований.

Минимальный конфиг nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## Безопасность

- **Защита от SSRF** ([`net_guard.py`](backend/app/net_guard.py)): прокси
  и запуск скана резолвят имя хоста и отклоняют приватные, loopback- и
  link-local адреса. Проверяется каждый хоп редиректа, содержимое не
  `image/*` не отдаётся. Без этого прокси выдавал бы облачные метаданные
  (`169.254.169.254`) и внутренние сервисы любому желающему.
- **Лимиты** ([`ratelimit.py`](backend/app/ratelimit.py)) не дают одному
  посетителю завалить чужой сайт запросами с вашего IP и получить бан.
- **Доступ к скану по токену**: результаты открываются только по
  непредсказуемому `scan_token`, он же хранится в localStorage браузера.
  Аккаунтов нет. Учтите: токен — это ссылка-секрет; кто её получил, тот
  видит скан, поэтому для разграничения прав между сотрудниками нужны
  полноценные аккаунты.
- **Экранирование вывода**: URL приходят с чужих сайтов и попадают в галерею,
  поэтому экранируются, а ссылки ограничены схемами `http(s)`.

## Разработка

Модули с нетривиальной логикой несут самопроверки:

```bash
docker compose exec app python -m app.net_guard    # → net_guard: ok
docker compose exec app python -m app.ratelimit    # → ratelimit: ok
docker compose exec app python -m app.scanner      # → scanner: ok
```

Структура:

```
backend/app/
  main.py            точка входа FastAPI, отдача фронтенда
  scanner.py         обход сайта, сбор картинок, оркестрация аудита
  models.py          схема БД: User → Project → Scan → Image
  net_guard.py       защита от SSRF
  maintenance.py     миграция схемы, ретенция, разбор оборванных сканов
  ratelimit.py       лимиты запуска сканов
  audit_technical.py HTTP-статус, формат, вес, размеры
  audit_copyright.py EXIF и оценка риска
  routes/            scan, gallery, export, proxy
frontend/            статика: галерея на ванильном JS
remove-images.php    скрипт удаления для WP-CLI
image_audit.py       предшественник: standalone-скрипт, генерирует HTML-отчёт
```

## Ограничения

- **SEO-аудита (alt/title) нет.** Он требовал повторной загрузки HTML под
  каждую картинку и замедлял скан в разы, поэтому убран.
- Счётчики лимитов живут в памяти процесса — рассчитаны на один
  uvicorn-воркер. При масштабировании переносить в Redis.
- Краулер без sitemap ограничен 100 страницами.
- EXIF читается только у растровых форматов; у SVG метаданных нет.
- Обратный поиск по картинке (TinEye) не подключён — риск считается
  только по EXIF, поэтому отсутствие метаданных не означает отсутствие
  чужих прав.
- Защита от SSRF не покрывает DNS-rebinding: между проверкой и запросом
  имя может переехать на внутренний адрес. Нужен коннектор с пиннингом IP.
